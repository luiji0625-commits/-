# AIオートメーション・フレームワーク

Claude Codeを「チャット」から「仕事を回す仕組み」に変えるための6要素。
AI活用が伸び悩む原因は、ツール不足よりも「仕事の渡し方が毎回バラバラ」なことにある。
プロンプトを上手くする前に、AIが迷わず動ける土台を作る。

## 6要素

| # | 要素 | 役割 | 例 |
|---|------|------|----|
| ① | **loop**（ループ） | 作業自動化 — 毎回同じ作業を回す | ニュース収集、CSV整形、リンク検証 |
| ② | **skill**（スキル） | 判断自動化 — 判断基準を固定する | note執筆ルール、公開前チェック、保存先ルール |
| ③ | **agent**（エージェント） | 専門分業 — 専門担当を分ける | 調査担当、レビュー担当、ブラウザ操作担当 |
| ④ | **goal**（ゴール） | 成果自動化 — 複数の作業を成果までつなげる | note作成 → X投稿 → サムネ作成 → 公開前チェック |
| ⑤ | **hook**（フック） | 安全制御 — 毎回必ず走らせる処理を決める | lint、test、危険コマンドの防止 |
| ⑥ | **MCP** | 外部接続 — 外部ツールと接続する | Slack、Figma、GitHub、データベース |

## まとめ

- ① loop　　作業自動化
- ② skill　　判断自動化
- ③ agent　　専門分業
- ④ goal　　成果自動化
- ⑤ hook　　安全制御
- ⑥ MCP　　外部接続

## この6つの関係

- **loop**は「何を繰り返すか」を決める。
- **skill**は「その中でどう判断するか」を決める。
- **agent**は「誰（どの専門AI）がやるか」を決める。
- **goal**は「複数の作業をどうつなげて成果に到達するか」を決める。
- **hook**は「何があっても必ず守るべき安全策」を決める。
- **MCP**は「外の世界（Slack・GitHub・DBなど）とどうつながるか」を決める。

この6つが揃うと、Claude Codeは単発の受け答えではなく、目標から逆算して自律的に動く仕組みになる。
