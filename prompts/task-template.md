# タスク依頼テンプレート

チートシートの「Claude用プロンプト例」（役割 / 目的 / 前提情報 / 手順 / 回答形式）を土台に、
41「目的定義」42「成功条件」43「入力設計」44「出力形式」を必須欄にしたもの。

コピーして埋める。**「成功条件」と「回答形式」が空のまま投げない。**

---

```
# 役割
（例: あなたはこの会社の業務設計を手伝うアシスタントです）

# 目的
（1文。何を達成したいのか）

# 成功条件
（これが満たされれば完了、と言える条件を箇条書きで2〜4個。
 「良い感じ」ではなく、第三者が○×を付けられる粒度で書く）
-
-

# 前提情報 / コンテキスト
（既存ファイル、既に決まっていること、制約、参考資料。
 「知らないはず」の情報はここに全部書く）

# 手順
（ステップ分解。分からない場合は「手順も含めて提案して」と書く）
1.
2.

# 回答形式
（出力先ファイル / 表の列 / 見出し構成 / 分量）

# やらないこと
（スコープ外。勝手に広げてほしくない範囲）

# 承認が必要な操作
（外部送信・公開・課金・削除がある場合、実行前に確認させる）
```

---

## 埋めた例

```
# 役割
あなたはこの会社の業務設計を手伝うアシスタントです。

# 目的
月次の経費精算の手順を、担当が変わっても回るドキュメントにする。

# 成功条件
- 初めての人が読んで、他の人に質問せず1回分を完了できる
- 使うツール名と画面名が具体的に書かれている
- 例外（領収書が無い / 締切を過ぎた）の対処が書かれている

# 前提情報 / コンテキスト
現状は口頭で引き継いでいて文書が無い。使っているのは（ツール名）。締切は毎月5日。

# 手順
1. 不明点を先にまとめて質問する
2. 回答をもとに手順書のドラフトを書く

# 回答形式
docs/expense.md に Markdown。番号付き手順 + 例外の表。

# やらないこと
ツールの乗り換え提案はしない。

# 承認が必要な操作
なし（ファイル作成のみ）
```
