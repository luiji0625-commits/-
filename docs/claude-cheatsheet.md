## Claudeワークフロー（知覚→推論→計画→行動）

```
1. 知覚（入力理解） → 2. 推論（考える） → 3. 計画（計画を立てる） → 4. 行動（実行する） → 1. へ戻る
                              すべて「目標（ゴール）」を中心に回る
```

## エージェントの種類
単タスク型 / マルチタスク型 / リサーチ特化型 / コーディング支援型 / ドキュメント処理型 /
カスタマー対応型 / マルチエージェント型

## ベストプラクティス
- 小さく始めて段階的に拡張
- 明確な目標と成功条件を定義
- 適切なコンテキストを与える
- 検証とフィードバックを徹底
- 安全性・制約を意識する
- 再利用可能な設計を行う
- 人とClaudeの協調を重視

## 評価指標
成功率 / 精度（正確性） / 応答時間（レイテンシ） / コスト（トークン・料金） / ユーザー満足度 / エラー率

## 基本コマンド例（Claude code）
| コマンド | 用途 |
|---|---|
| `/test` | テスト実行 |
| `/tools` | 利用可能なツール確認 |
| `/memory` | メモリ・コンテキスト確認 |
| `/reset` | セッションリセット |
| `/health` | システム・接続確認 |
| `/mcp` | MCP接続一覧 |
| `/help` | ヘルプ表示 |

> 注: これは画像の記載どおり。実際の Claude Code に存在するのは `/mcp` `/help` `/memory` などで、
> `/test` `/tools` `/health` `/reset` は環境により無い。使う前に `/help` で実在を確認すること。

## プロンプトのコツ / よくあるミス

| コツ | 対になるミス |
|---|---|
| 役割を明確にする | 目的が曖昧 |
| 目的・制約を具体的に書く | 情報不足・コンテキスト不足 |
| 出力形式を指定する | 指示が曖昧・複雑すぎる |
| ステップ分解して指示する | 出力形式未指定 |
| 例を示す (Few-shot) | 検証・テスト不足 |
| 検証基準を明記する | 安全性・制約の見落とし / ツール設定ミス |

## 成熟度レベル
1. 学習（理解する） → 2. 構築（作って試す） → 3. 導入（小さく使う） → 4. 最適化（改善し続ける） → 5. 拡張（スケールする）
